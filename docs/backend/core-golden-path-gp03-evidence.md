## Implementation and boundary adaptation

- Identity ports and use-case implementations now live under `identity.application.ports.{in,out}` and `identity.application.usecases`. The confirmation coordinator remains identity-owned and preserves the atomic token → user → ordered classes → enrollments → token protocol.
- `classroom` was renamed to `academic`; its ports and orchestration are under `academic.application`. `AcademicPolicy` remains pure; store/serializer/idempotency effects are application coordination.
- Identity operation DTOs/results/projections moved from `identity.domain.models` into `identity.application.models` (36 declarations). Pure `User` and `SessionRecord` domain concepts remain.
- Academic operation models/state projections moved to `academic.application.models`; pure domain concepts remain. `AcademicPage` is temporarily published as immutable `academic.domain.contracts.AcademicPage` because downstream features still consume this technical page projection; the application package retains a typealias. Bounds/defensive-copy tests cover construction.
- `AuthenticatedActor` is temporarily published as `identity.domain.contracts.AuthenticatedActor` because legacy domain callers still need minimal actor facts while their GP-04 use-case migration is pending. The internal session-validation reference is opaque, used only for identity revalidation, and redacted from `toString`. GP-04 must remove transitional domain exports once their consumers migrate.
- To prevent a `SessionRecord` from crossing into other feature adapters, `ResolveAuthenticatedActorInputPort` is the cross-feature actor boundary and returns only `AuthenticatedActor`. Its identity-owned use case delegates to the full `ResolveSessionInputPort` internally, preserving cookie hashing, revocation/expiry checks, and session revalidation. Feature controllers and the file-upload session filter use only the actor port. Full `SessionRecord` resolution remains in identity-owned HTTP endpoints that need the session response. A direct test checks the port's declared return type and actor mapping/redaction.
- `AcademicPage` now recursively snapshots and wraps the actual collection-valued page fields (`studentIds`, `teachers`, `publicationIds`, student `enrollments`, and nested enrollment ID lists), in addition to row/list copies. The direct test mutates both source and returned nested maps/lists and verifies the page is unchanged. This guarantee covers collection-shaped values; it does not claim arbitrary opaque `Any?` leaf objects are deeply immutable.
- Corrected the shared PSI selector to report `classroom` package/descendants as obsolete while accepting `academic`; fixtures now include valid `AcademicFeature.kt` and invalid `ClassroomFeature.kt`.
- After ArchUnit identified concrete cross-feature callers, 78 affected DTO/model declarations moved from owning `domain.models` to `application.models` (69 actor-bearing and 16 page-bearing, with overlap). A separate 144 directly implicated orchestration declarations moved from legacy `domain.ports`/`domain.usecases` into application packages: 69 inbound ports and 69 paired use cases, two output ports, and four additional reported use cases (`health.CheckServiceHealthUseCase`, `materials.ProvisionQuestionImageUseCase`, `outbox.PublishPendingEventsUseCase`, `outbox.RedriveOutboxEventUseCase`). This is a bounded D-01/D-05 package/ownership adaptation, not a claim that GP-04 flows have completed typed behavior redesign. No SQL/schema behavior changed.
- The Platform rollback failure was a test-path defect: Kotlin `run {}` called stdlib instead of the runner. The test now passes explicit `TransactionRunDto`, proving rollback through the actual runner. Curriculum last-admin concurrency returned `[200,500]` because a typed conflict was not mapped; application now surfaces `AcademicConflict` and the PostgreSQL race test returns `[200,409]`.
